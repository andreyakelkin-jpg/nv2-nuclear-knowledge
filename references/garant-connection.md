# ГАРАНТ через веб-интерфейс

Вход: [account.garant.ru](https://account.garant.ru/). Документы:
[internet.garant.ru](https://internet.garant.ru/). Платный API не используется и не требуется.
Учётные данные и cookies не хранятся в плагине. Авторизация остаётся в управляемом браузере;
в новом окружении может потребоваться повторный вход.

## Явный запуск

Настройка `allow_implicit_invocation: false` отключает неявное подключение навыка. Вызовите
`$garant-documents` или прямо попросите «Скачай из ГАРАНТ … и добавь в базу» / «Проверь в ГАРАНТ
актуальный статус …». Другие навыки переходят к этому сценарию только после такого запроса.
Установка плагина, `doctor`, поиск по локальной базе и отсутствие документа не открывают сайт.
Флаг локальной команды `--explicit-request` означает, что исполнитель проверил наличие запроса;
сам CLI не анализирует разговор и никогда не обращается к сети.

## Работа в браузере

Прочитайте инструкции доступного инструмента управления браузером. Предпочитайте существующую
доступную сессию ГАРАНТ. Если её нет, откройте страницу входа. У наблюдавшегося 12 сентября 2026
интерфейса два шага: поле «Логин или телефон» → «Войти», затем «Пароль» → «Войти».
Названия служат ориентирами: определяйте поля заново по текущему интерфейсу, без сохранённых индексов.
Не сохраняйте URL входа с `login_challenge`, callback-параметрами или служебными данными в отчёты.

Переданные пользователем для этого входа учётные данные можно использовать согласно правилам
браузерного инструмента. Если их нет, пользователь входит сам. Не включайте сохранение пароля без
разрешения. Если появляется «Ваш логин и пароль уже используются», сообщите о занятом сеансе;
пользователь должен освободить его или предоставить доступную вкладку. Не разрывайте чужое соединение,
не заполняйте заявку в поддержку и не выполняйте бесконечные повторы.

После входа ищите точный документ. Проверяйте статус в карточке/юридической справке и выбранную
редакцию в списке редакций. Будущая редакция не равнозначна действующей; новый документ может ещё
не вступить в силу. При расхождении с локальной копией сообщите реквизиты обеих редакций.
В проверенном интерфейсе: «О документе» → «Справка» содержит основания и даты изменений;
«Редакции» открывает историю; над текстом отображается «Актуальная ред.» с интервалом действия.
Не переносите отметку актуальности редакции в поле юридического статуса всего документа.
Не угадывайте недоступные поля. Основа сценария — штатные функции
[работы с документами ГАРАНТ](https://ask.garant.ru/training/dokumenty-v-sisteme);
элементы рабочего интерфейса проверяются заново при подключении.

Для скачивания используйте штатный экспорт в PDF с приложениями. Уточнённый пользователем порядок:
открыть вкладку **«Документ»** → нажать **дискетку «Сохранить в файл»** в правом верхнем углу
панели документа → выбрать **PDF** → нажать **«Сохранить документ целиком»**.
Перед последним нажатием проверьте видимое выделение PDF в меню. Если панель или меню не помещаются
в окне, используйте семантический локатор либо сначала сделайте элемент видимым и проверьте его заново;
не нажимайте по координатам за пределами окна или по устаревшему индексу. Не подменяйте этот путь
ссылкой «О документе → Графическая копия документа».
Пункты сохранения выделенного фрагмента не подходят для архивирования полного документа.
Перед экспортом создайте билет `begin-export` для папки загрузок, затем используйте `collect-export`:
путь к новому завершённому файлу определяется автоматически. Пользователю не нужно прикреплять
файл повторно или сообщать его имя. Если браузер открыл отдельное окно сохранения, обработайте его
доступным разрешённым инструментом. Не выдавайте HTML страницы входа, снимок экрана или краткий
фрагмент за нормативный документ.
При проверке во встроенном браузере Codex вход, справка и редакции работали, но штатная команда
экспорта не вернула событие скачивания или доступный локальный файл. Это ограничение проверки
данного окружения, не доказательство отсутствия экспорта у подписки. Теперь `collect-export` проверяет
саму папку загрузок независимо от события браузера. Если файл не появился и системный диалог
недоступен, сохраните билет для продолжения и укажите этот конкретный блокер; не вызывайте скрытый API.
RTF/ODT сохраняйте как исходный экспорт, а для архива потребуется безопасное преобразование в
поддерживаемый формат с отдельной проверкой исходника и результата и сверкой таблиц/приложений.
Не обходите безопасность архива ради неподдерживаемого формата.

## Локальная фиксация наблюдений

`RUNNER garant connection` выводит адреса сайта без сетевого соединения.
Создайте `observation.json` по реально прочитанной странице. Пример формы (значения заменяются
фактическими; это не сведения о статусе конкретного документа):

```json
{
  "source_url": "https://internet.garant.ru/#/document/10103000",
  "title": "Точное название открытого документа",
  "checked_at": "2026-09-12T12:00:00+03:00",
  "provider_status": null,
  "revision_label": null,
  "revision_status": null,
  "effective_from": null,
  "effective_to": null,
  "uncertainty": null,
  "observation_text": "Фактически прочитанные сведения о статусе и редакции."
}
```

Обязательные поля: `source_url`, `title`, `checked_at`, `observation_text`. Остальные — строки или
`null`; статус нельзя заполнять по памяти. Время проверки содержит часовой пояс и не может быть
будущим. Дополнительные ключи отклоняются, чтобы не переносить конфигурацию/учётные данные.
Снимок страницы при необходимости сохраняйте отдельно, исключив сведения входа; укажите его путь
в `observation_text`. JSON — запись наблюдения агентом, не автоматическое доказательство сайта.

```text
RUNNER garant record observation.json --explicit-request
RUNNER garant record observation.json --source "ABSOLUTE_DOWNLOADED_FILE.pdf" --explicit-request
```

Без файла команда сохраняет сведения в `STATE_ROOT/garant/checks/<topic>-<unique>/evidence.json`.
С файлом — копирует экспорт и сохраняет отчёт в `STATE_ROOT/garant/downloads/<topic>-<unique>/`.
Пути состояния разрешаются по [настройке платформы](platform-setup.md). Старые результаты не
перезаписываются; рабочий корпус не меняется. `evidence.json` записывается последним и обозначает
готовый пакет; при ошибке записи неполный каталог может остаться и не считается готовым результатом.

Отчёт содержит источник, время, topic, SHA-256 копии (при наличии),
`evidence_level: reference_system`, `official_status_verified: false` и требование экспертной проверки.
Файл сохраняется как `not_checked` / `not_archived`. Затем выполните архивный сценарий навыка.
Внешний источник не освобождает файл от проверок безопасности, а статус в справочной системе не
повышает экспертный допуск. Не публикуйте выгрузки и отчёты вместе с кодом плагина.

## Автоматическое добавление после экспорта

```text
RUNNER garant begin-export observation.json --explicit-request
RUNNER garant collect-export TICKET --explicit-request
```

По умолчанию используется папка `Downloads` текущего пользователя. `--download-dir` у `begin-export`
задаёт другую папку; она должна совпадать с фактическим назначением браузера. Снимок папки делается
до экспорта, поэтому старые документы не подбираются. Команда получения проверяет стабильный размер
и время изменения, ждёт исчезновения частичных файлов и отказывается выбирать среди нескольких
кандидатов. Для нескольких файлов предусмотрен `--expected-name` с именем, наблюдавшимся в браузере.
`--wait-seconds` ограничен 60 секундами. Технический повтор одного билета возвращает тот же пакет.
Это разовый импорт в рамках явного запроса, без службы наблюдения и автоматического входа.

После получения файла агент сам продолжает проверки и Архиварий, готовит карточку и решение и запускает:

```text
RUNNER kb apply DECISION_FILE --garant-evidence EVIDENCE_FILE
RUNNER garant import-status EVIDENCE_FILE
```

Первая команда связывает проверенный оригинал с источником ГАРАНТ в `source.garant`, сохраняет документ
и обновляет индексы. Вторая сверяет SHA-256 с опубликованным реестром и реальным оригиналом в базе,
возвращая `archived: true` и путь карточки только при совпадении. Ею же проверяйте дубли до staging и
результат после неоднозначного завершения `apply`; не запускайте `apply` повторно вслепую.
Первичный `evidence.json` остаётся неизменным свидетельством получения: текущий результат импорта
определяется реестром, а не его начальным полем `archive_status: not_archived`.
